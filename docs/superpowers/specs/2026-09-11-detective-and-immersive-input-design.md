# 趣味输入组件与侦探解谜设计

日期：2026-09-11

## 背景

当前剧情分支使用可见 `textarea` 接收完整回复。它能完成分支判断，但用户感受到的是填写表单，而不是在练习文本上直接打字；同时，剧情页没有普通练习中的键盘指法区域。后续侦探解谜也需要逐段输入，如果继续为每种玩法单独实现输入逻辑，会造成交互和状态计算重复。

本次改动先建立一套可复用的“趣味输入组件”，用它重做剧情分支输入，再实现侦探解谜。

## 目标

- 剧情分支不显示可见输入框，用户直接键入，回复选项中的字符随输入变色。
- 剧情分支恢复虚拟键盘；桌面端直接显示，窄屏端默认收起且可手动展开。
- 多候选回复可以随输入自动识别，不要求用户先点击选项。
- 侦探解谜通过输入证词解锁线索，最后输入嫌疑人或关键证据完成指认。
- 剧情和侦探共用输入状态与字符渲染规则。
- 保持纯前端、本地优先、免登录，不引入新依赖或后端。

## 非目标

- 本轮不实现限时破案、排行榜、案件存档或结局图鉴。
- 本轮不增加多个案件；先交付一个完整可玩的案件。
- 本轮不让浏览器执行用户输入的任何命令或代码。
- 本轮不重构普通练习的完整状态机。

## 方案选择

### 采用：输入即识别候选

页面同时展示所有可选回复。用户直接输入，系统根据当前文本计算每个候选的匹配长度；匹配最接近的选项保持强调，其他选项逐渐变暗。输入完整匹配某个选项后自动推进剧情。

这个方案比“先点击选项再输入”少一步操作，也最符合“根据输入亮某个字”的预期。相比保留可见输入框，它能直接复用普通练习的正确、错误和当前位置视觉语言。

### 未采用：先点击选项再输入

状态简单、目标明确，但用户会先做一次选择再机械抄写，输入本身不再承担选择作用。

### 未采用：为每个玩法单独实现输入

短期代码少，但剧情、侦探、诗词补全等玩法会逐渐产生不同的退格、输入法和字符状态规则，维护成本更高。

## 共用趣味输入状态

新增一个纯逻辑模块，输入为候选文本数组和当前输入值，输出为：

- 每个候选的逐字状态：`pending`、`current`、`correct`、`wrong`。
- 每个候选从开头连续匹配的字符数。
- 当前最可能的候选集合。
- 下一字符集合。
- 是否完整匹配，以及匹配到的候选索引。

规则如下：

1. 输入为空时，所有候选的第一个字符标记为 `current`。
2. 已输入位置逐字比较；相同标记为 `correct`，不同标记为 `wrong`。
3. 连续匹配长度最高的候选为当前候选；并列时同时保留强调。
4. 非当前候选在用户开始输入后降低透明度，但仍可见。
5. 当前输入与某个候选完全相同时完成选择。
6. 退格只改变当前输入值，字符状态随状态函数重新计算。
7. 中文输入遵循 `compositionstart` / `compositionend`，输入法组词期间不提前判定。

逻辑模块不直接操作 DOM，剧情和侦探只消费其结果，因此可以通过 Node 测试覆盖。

## 剧情分支交互

### 输入区域

- 删除可见的“你的回复”文本框。
- 在剧情页面保留一个视觉隐藏、可聚焦的输入元素。
- 点击剧情卡片或选项区域时重新聚焦隐藏输入。
- 每个回复拆成字符节点，使用普通练习相同的绿色、红色和当前位置样式。
- 页面提供简短提示：“直接输入你选择的回复”。

### 虚拟键盘

- 趣味页面增加独立键盘容器，复用现有 `renderKeyboard`。
- 英文、拼音、数字和符号可以高亮下一物理按键。
- 中文输入依赖输入法，无法可靠预判具体物理按键；此时显示键盘作为指法参考，不虚构按键提示。
- 桌面端默认展开。
- 980px 以下默认收起，提供“显示键盘 / 收起键盘”按钮。
- 键盘展开状态仅保留在当前页面会话中，不新增持久化设置。

### 分支推进

- 完整匹配一个回复后播放当前完成音效并进入下一节点。
- 新节点加载后清空输入并重新聚焦。
- 到达结局后移除输入焦点，保留“再玩一次”和“返回全部玩法”。

## 侦探解谜流程

首个案件采用非程序员题材的日常悬疑故事，结构为：

1. **案件简介**：说明地点、失物或事件以及调查目标。
2. **证词一**：用户逐字输入证词，完成后解锁第一条线索。
3. **证词二**：完成后解锁第二条线索。
4. **证词三**：完成后解锁第三条线索。
5. **线索整理**：集中展示已经获得的线索，明确其中存在一处时间、位置或物品状态矛盾。
6. **最终指认**：用户输入嫌疑人姓名或关键证据；允许数据中配置多个等价答案。
7. **结果**：正确时说明推理链，错误时不结束案件，给出温和提示并允许退格或重新输入。

第一案使用“雨夜画廊失窃案”：闭馆后的画廊停电数分钟，一幅小画从上锁展柜中消失。三名相关人员的证词分别包含时间、钥匙和雨水痕迹信息。答案只依赖页面已展示的线索，不要求外部知识。

## 侦探数据结构

案件数据与视图逻辑分离。每个案件包含：

- `id`、标题、简介和开始阶段。
- 有序证词列表；每项包含说话人、证词文本和完成后解锁的线索。
- 最终问题、可接受答案数组、错误提示。
- 正确结果标题、推理说明和结案文本。

证词只有一个目标文本，复用趣味输入组件的单候选模式；最终指认使用多候选答案模式，但页面不直接展示答案字符。

## 菜单与页面状态

- 侧边栏“侦探解谜”从禁用状态改为可点击，并标记“玩”。
- “全部玩法”中的侦探卡片改为“现在可玩”。
- 点击侦探入口进入案件介绍页，再点击“开始调查”进入证词流程。
- 顶栏显示“侦探解谜 / 雨夜画廊失窃案”。
- 普通练习、剧情、侦探、全部玩法、历史和外部游戏仍是互斥主视图。

## 错误处理与边界

- 空输入不显示错误。
- 输入出现不匹配字符时，对应位置显示红色，并提示可退格修正。
- 输入长度不得超过当前最长候选文本。
- 输入法正在组词时不推进节点。
- 案件数据引用不存在的阶段、空证词、空答案或不可到达的结案状态必须由测试阻止。
- 页面切换、重玩和重新开始案件时必须清空趣味输入状态。

## 可访问性

- 隐藏输入保持可聚焦，但不从辅助技术中隐藏其输入用途。
- 字符颜色之外同时使用 `correct`、`wrong` 等语义类和状态提示文本。
- 键盘展开按钮包含 `aria-expanded`。
- 新剧情节点、线索和结案结果使用礼貌型动态播报。
- 所有操作都可以只用键盘完成。

## 测试策略

### 单元测试

- 空输入时所有候选首字为当前位置。
- 输入前缀时正确字符点亮，候选正确收敛。
- 错误字符标红，退格后恢复。
- 完整输入返回正确候选索引。
- 中文 Unicode 字符按字符而不是 UTF-16 单元处理。
- 单候选证词模式与多候选剧情模式使用相同状态函数。

### 数据测试

- 剧情所有分支仍可到达有效结局。
- 侦探案件至少有三段证词、三条线索和一个有效答案。
- 所有阶段引用有效，证词和答案非空。

### 回归验证

- 现有普通练习状态测试、存储测试和剧情数据测试继续通过。
- JavaScript 语法检查和 `git diff --check` 通过。
- 桌面宽度验证键盘默认展开；窄屏验证默认收起且能展开。

## 实施边界

本轮只完成共用趣味输入组件、剧情输入改造、响应式虚拟键盘和一个侦探案件。记忆闪打、成语接龙及路线图中的其他功能继续保留为后续事项。
